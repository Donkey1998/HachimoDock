## 零基础补给站

讲解里出现的术语，先在这里过一遍再往下读：

| 术语 | 一句话解释 |
|---|---|
| 固件（firmware） | 烧进硬件设备里、让设备能工作的程序。电脑上叫"软件"，芯片里叫"固件" |
| 交叉编译 | 在你的 Windows PC 上编译出**给另一颗 CPU（ESP32-P4）执行**的程序。因为芯片性能弱，不能在自己身上编译 |
| 工具链 | 编译器+链接器+烧录工具的组合，好比安卓的 "JDK + SDK + adb" 全家桶 |
| 烧录（flash） | 把编译出的固件写进芯片的 Flash 存储器，类似给手机刷机 |
| 串口 / 波特率 | 设备和 PC 之间最古老的对话通道；波特率=每秒传多少位，双方必须约好同一个数（本项目是 4,000,000） |
| SDK / 框架 | 芯片厂商提供的"开发套件"。ESP-IDF 就是乐鑫官方 SDK，≈ 安卓世界的 Android Framework |
| pytest | Python 的测试框架，`pytest xxx_test.py -q` 自动跑文件里的测试函数 |

**怎么用 `文件:行号` 引用**：`main/pet_p4_main.c:590` 表示"main 目录下 pet_p4_main.c 文件的第 590 行"。在 VS Code 里 `Ctrl+G` 输入行号直达；命令行用 `sed -n '590p' 文件名` 打印该行。

## 讲解

### 1.1 这个项目是什么

HachimoDock（哈基米机）是一套「PC 桌面管理器 + ESP32-P4 小屏固件」的组合产品：PC 上的 AI Agent（Claude Code、Codex 等）工作时，状态经 USB 同步到桌搭小屏，驱动宠物动画与气泡；实体按键、摇杆、麦克风把操作和语音送回 Agent。

```
Agent 会话（Claude Code / Codex / …）
      │
Tauri 桌面端（Rust + React）── Node Bridge sidecar（状态聚合）
      │
      │  USB（板上跳线二选一：CH343 串口桥 ──或── 原生 USB OTG）
      ▼
┌─ ESP32-P4 固件（本课程学习对象）────────────────┐
│  协议分发 → 状态/对话/资产 → 渲染 → MIPI-DSI 屏   │
│  按键/摇杆/触摸/麦克风 ←── 输入采集 → 上行 JSON    │
└─────────────────────────────────────────────┘
```

关键认知：**固件内外的唯一通道是 USB**。所有功能——宠物动画、语音对话、组件推送、OTA 升级——都跑在这一条链路上（协议规范 [protocol.md](../protocol.md)，约 59KB，第10课再精读选段）。

### 1.2 从 51 单片机到 ESP32-P4：三个心智转变

你写过 51，这反而是优势——很多底层直觉还在。需要更新的是三个模型：

**转变一：寄存器 → HAL 驱动 API**
51 时代你直接写 SFR：`P1 = 0xFF` 点灯。ESP32-P4 上点一个 GPIO 要先 `gpio_config()` 配置方向/上拉，再 `gpio_set_level()` 控制。中间隔着乐鑫的驱动层。好处是换芯片不用重写业务，代价是要学一套 API 体系。

**转变二：裸机大循环 → FreeRTOS 多任务**
51 是一个 `while(1)` 轮询一切。P4 是双核 RISC-V + FreeRTOS：每个功能一个任务（可理解为线程），调度器按优先级分时。本固件有 10 个任务 + 1 个主循环（第03课全景）。

**转变三：一整块程序 → 分区 + 组件**
51 的程序一锅烧进 ROM。P4 的 32MB Flash 被**分区表**（[partitions.csv](../partitions.csv)）切成：NVS 键值存储、两个 OTA 槽（A/B 轮流升级）、SPIFFS 文件系统、两个 10MB 形象槽。代码本身也由**组件**拼装（第02课）。

### 1.3 搭环境、构建、烧录

1. 通读 [README.md](../README.md) 的硬件方案与快速开始、[BUILD.md](../BUILD.md) 的工具链版本矩阵——**版本号要严格对齐**（Python 3.10+、esptool 5.4.0）。
2. Windows 下用 `tools/p4.ps1` 一键构建/烧录；或直接 `pio run`（PlatformIO 会自动拉 ESP-IDF 工具链）。
3. 烧录成功后连接 PC 打开 Pet Manager 桌面端，确认宠物显示、按键有响应。
4. 无需硬件也能跑的**主机侧测试**（仓库根目录）：`python -m pytest firmware/tests -q`。

## 练习

1. **🔧动手**：完成构建 → 烧录 → 桌面端连接的完整流程，记录你遇到的第一个报错及解法（这些笔记将来最值钱）。
2. **🔧动手**：在仓库根目录跑 `python -m pytest firmware/tests -q`，记录通过数。找到其中测试**输入逻辑**的那个测试文件名（提示：input）。
3. **📍阅读**：打开 `partitions.csv`（9 行），数一数 Flash 被切成了几个区，各叫什么名字、多大。
4. **💭思考**：为什么要有两个 10MB 的 `appearance` 槽，而不是一个 20MB 的？（提示：升级时的原子性）
5. **💭思考**：USB 链路上跑的是「PC → 固件」的下行和「固件 → PC」的上行。各举两个例子：什么数据该下行、什么该上行？

## 自测与参考答案

- **练习2**：`tests/p4_input_logic_test.py`（还有更多，第05课会用到它）。
- **练习3**：8 个区：`nvs` 24K（键值存储）、`phy_init` 4K（射频校准数据）、`ota_0`/`ota_1` 各 2.5MiB（应用双槽）、`otadata` 8K（**A/B 槽切换指针**，第11课"原则二"的主角）、`storage` 6.875MiB（SPIFFS）、`appearance0`/`appearance1` 各 10MiB（形象双槽）。
- **练习4**：形象包升级时先写空闲槽、校验通过再切换——坏的形象包永远不会破坏正在使用的那个。和 A/B OTA 同一思想。
- **练习5**：下行如状态同步（`state/...`）、语音播放音频；上行如按键事件（`input/event`）、麦克风音频（`audio/chunk`）。

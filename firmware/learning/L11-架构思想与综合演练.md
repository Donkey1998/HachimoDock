## 零基础补给站

| 术语 | 一句话解释 |
|---|---|
| fail-open / fail-closed | 校验环节出故障时的两种默认：放行（保可用性）vs 拒绝（保安全性）。门禁系统断电时门开还是门锁死，就是这道选择题 |
| 原子性 | 一个操作要么完整发生、要么完全没发生，不存在"做了一半"。形象包的形象槽切换就是原子换——要么旧形象要么新形象，没有"半张脸"状态 |
| 回滚（rollback） | 新版本出问题自动退回旧版本。前提是旧版本还在——这就是 A/B 双槽的物理意义 |
| 幂等 | 同一操作做一次和做 N 次效果相同。网络重传时不怕重复执行（收到重复的"开灯"指令不会有什么坏事） |

## 讲解：七条架构原则

### 原则一：防御式初始化（第04课）

所有外设 init 尽力而为、失败降级不阻塞启动：ES7210 不在→ES8311 双工；AEC 失败→半双工；LCD 失败→跳过触摸。**保护的生命线是 USB 通信与 OTA 回滚**——设备再坏也得能被修复。代价是各模块都要处理"自己可能没初始化"的状态。

### 原则二：A/B 双槽 + 健康确认（partitions.csv / pet_p4_ota.c）

`ota_0/ota_1` 轮流写入，新固件启动后必须**确认健康**才标记可引导，否则回滚旧槽。和安卓 A/B 系统更新同源：升级永远可逆，坏固件自动退回。形象槽 `appearance0/1` 同理。

### 原则三：fail-closed 写入安全（第09课）

原生 USB 大文件写入前：随机 nonce 挑战 + 设备 ID（MAC 派生）唯一性校验，校验不过**直接拒绝**。安全默认值是"拒绝"而非"放行"——说"不"的代码路径要短且不可绕过。

### 原则四：优先级即语义（第03课）

任务优先级表（音频 18 > 协议 11 > 输入 9 > 触摸 8）直接编码"什么最不能断"。优先级不是调出来的玄学，是**团队对产品价值观的书面约定**。

### 原则五：坐标系分离（第07课）

业务层永远画 640×480 横屏逻辑帧，"旋转"这种硬件烦恼由 PPA 一层消化。接口两侧各自守最自然的坐标系，转换收拢在管线一处（代价：触摸侧要做竖屏换算）。

### 原则六：精确控制依赖（第02课）

空壳 stub 顶掉不想要的组件、override 保住要改的组件、BSP 只取 bring-up 能力、LVGL 只当字体引擎用。**厂商代码进镜像的每一行都应是知情决定**——镜像尺寸（2.5MB OTA 槽）逼出了这种纪律。

### 原则七：可测试性 = 纯逻辑与硬件剥离（第05课）

输入解码器（input_core）、游戏引擎（game）、PetUI 校验器（petui_validator）都写成零依赖、无 malloc 的纯逻辑，能在 PC 上编译，pytest 锁行为；协议契约测试锁三端一致。**嵌入式代码不是天生不可测，是分层没分好**。

### 一张安卓对照表（带走）

| 本项目做法 | 安卓世界亲戚 |
|---|---|
| best-effort init + 降级 | `START_STICKY` + 各组件判空自保 |
| A/B OTA + 健康回滚 | A/B system update + rollback |
| topic 路由 + requestId + ACK | AIDL + Bundle 的 correlationId + oneway 回调 |
| g_protocol_queue 单消费者 | `Service` + 单 Looper 串行处理 |
| 契约测试锁三端 | 接口层单测 + API 兼容性检查（apiLint 思想） |

## 综合演练：新增一个温度传感器

这是本课程的毕业设计。假设要给设备加一颗 I2C 温度传感器（如 SHT30，地址 0x44），每 30 秒上报一次温度，并能经 PC 查询。**先自己写清单，再对照参考答案**。

提示路径（按课程顺序回忆）：
- 第02课：驱动从哪来？（托管组件 registry 有没有现成的？没有就自己写——放哪个目录？）
- 第06课：怎么挂上现有 I2C 总线？要不要探测回退？
- 第03课：谁负责 30 秒周期？（新任务还是挂在现有任务？优先级定多少？）
- 第10课：协议加什么 topic？PC 端要改什么？契约测试要不要加断言？
- 第04课：初始化失败怎么办？

## 参考答案（毕业演练对照）

参考改动清单（你的可以不同，但每项都要有理由）：
1. **驱动**：查 registry 无现成则自写 `components/sht30`（或放 main 内简单驱动），实现 `sht30_init(i2c_bus, addr)` / `sht30_read_temp()`。
2. **接入**：复用 BSP 的 I2C 总线句柄；`i2c_master_probe(0x44)` 探测，不在位则该功能静默禁用（原则一）。
3. **任务**：新建低优先级任务（如 5，低于触摸）或挂进现有周期框架，30s 读一次；量小不值得高优先级（原则四）。
4. **协议**：新增上行 topic `sensor/temperature`（payload 含 value/timestamp），下行查询 `sensor/query`；同步更新 protocol.md **和** 契约测试断言（原则七的契约面）。
5. **PC 端**：Rust 侧解析新 topic，可选 UI 显示。
6. **初始化**：放在 `pet_p4_touch_init` 之后同段，失败仅 LOGW（原则一）。

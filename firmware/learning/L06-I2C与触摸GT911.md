## 零基础补给站

| 术语 | 一句话解释 |
|---|---|
| 总线（bus） | 多个设备共享的一组通信线——一条公路多个门牌。挂上去的设备越多越省引脚，代价是同一时刻只能一对设备说话 |
| I2C | 两线总线：SCL（时钟，主控喊节拍）+ SDA（数据）。所有设备并联，靠地址区分 |
| 7 位地址 | 每个 I2C 从设备的"门牌号"（如 GT911 是 0x5D）。主控发地址+读/写方向，被点名的才应答 |
| 外设芯片的寄存器 | 触摸芯片内部的一排"小抽屉"，主控往某抽屉写=下命令，从某抽屉读=取数据。和 CPU 寄存器是两回事 |
| 开漏+上拉 | I2C 的电气设计：设备只往低拉、不往高推，高电平靠总线上统一的电阻实现——这样多设备共享也不会短路（知道有这回事即可） |
| 轮询 vs 中断 | 轮询=定时去问"有了吗"；中断=对方主动按铃。轮询省事有延迟，中断实时但复杂。本课触摸选了轮询 |
| 适配器模式 | 接口转换层——安卓开发者天天用的设计模式，本课"panel IO"就是硬件版：把 I2C 读写包装成统一接口，让触摸驱动不关心底下是什么总线 |

**坐标系提醒**：触摸报的坐标是**屏幕物理坐标系**（480 宽×640 高，原点在左上）——和第07课要讲的"逻辑横屏"不同，先记住这个伏笔。

## 讲解

### 6.1 I2C 是什么：两根线上的小局域网

I2C 是**主从式两线总线**：SCL（时钟）+ SDA（数据），所有设备并联在这两根线上，靠 **7 位地址**区分谁在说话。主控（P4）永远是主机，按地址呼叫某个从设备，读写它的寄存器。

本板这条总线上挂了三个从设备：

| 设备 | 地址 | 用途 |
|---|---|---|
| GT911 触摸芯片 | 0x5D（或 0x14，见 6.2） | 报触摸坐标 |
| ES8311 | 0x18 | 播放 codec（第08课） |
| ES7210 | 0x40 | 采集 codec（第08课） |

总线参数：SCL=GPIO8、SDA=GPIO7，I2C 控制器 1，400kHz 快速模式（BSP 的 `bsp_i2c_init()` 惰性初始化——第一次被任何模块用到时才建）。ESP-IDF 新式 API：`i2c_new_master_bus()` 拿总线句柄，后续所有设备都往这个句柄上挂。

**和安卓类比**：I2C 总线 ≈ 一条共享总线上的多个 Service，地址 ≈ Intent 的 target component；`i2c_master_probe(addr)` ≈ `resolveService()` 探测在不在。

### 6.2 GT911 接入：探测、封装、轮询（`main/pet_p4_touch.c`）

**地址探测（:93-98）**：GT911 的 I2C 地址由上电时 INT 脚电平决定，硬件配置不同可能是 0x5D 或 0x14。固件先 `i2c_master_probe(0x5D)`，失败再试 0x14。这是嵌入式的万能模式："**外设可能在也可能不在，先探测再决定**"——第08课的 codec 探测是同款。

**三层封装**（:92-119 的初始化代码）：

```
i2c 总线 (bsp_i2c_init)
   └→ esp_lcd_new_panel_io_i2c()      // 把"对 GT911 读写寄存器"封装成 panel IO
        └→ esp_lcd_touch_new_i2c_gt911() // 托管组件的触摸驱动，输出坐标
```

为什么中间要套一层 panel IO？因为 ESP-IDF 的屏幕框架统一用 `esp_lcd_panel_io` 抽象"命令通道"（不管底下是 I2C 还是 SPI），触摸驱动复用这层抽象就能同时支持两种接口的触摸芯片。**适配器模式的硬件版**。

**轮询读取**：`pet_p4_touch` 任务（:128 创建，优先级 8）每 `PET_P4_TOUCH_SAMPLE_MS`(15ms，:24) 读一次坐标。GT911 也能配中断模式（INT 脚），但本项目选轮询——省一根线的心智负担，15ms 对触摸完全够。

### 6.3 手势解码状态机（`main/pet_p4_touch_core.c`）

原始数据只是"按没按 + 坐标"，手势是**软件状态机**算出来的。核心函数 `pet_p4_touch_decoder_update()`（:42 起）：

- 按下瞬间：记录 `start_x/start_y/start_ms`，等待后续（:54-60）
- 按住超过 `long_press_ms`：发长按事件，且只发一次（`long_press_emitted` 标志，:62-66）
- 松开：根据位移和时长判定是轻点还是滑动

解码器参数有默认值（滑动阈值 40px、长按 700ms，:22-23），由调用方传入覆盖。输出的**事件结构体**（`fill_event`，:26-40）有六个语义字段：

| 字段 | 来源 |
|---|---|
| `gesture` | 状态机判定（轻点/长按/滑动…） |
| `x`/`y` | 当前触摸坐标 |
| `dx`/`dy` | 当前点减起点（滑动向量） |
| `duration_ms` | 按住时长 |

注意 `touch_core.c:6-7` 定义了 `PET_P4_PANEL_WIDTH 480 / HEIGHT 640`——坐标是**面板物理坐标系**（竖屏），和第07课要讲的"逻辑横屏坐标系"不同，UI 层需要换算。

事件最终经 16 深队列 → 主循环消费 → 产出 `input/event` JSON 上行给 PC。

### 6.4 一图总结数据流

```
GT911 芯片 --I2C--> esp_lcd_touch 驱动 --15ms轮询--> 坐标
   --> touch_core 状态机 --> 事件(手势+坐标+时长) --> 队列
   --> 主循环 pet_p4_touch_process --> input/event JSON --> USB 上行
```

## 练习

1. **📍阅读**：读 `main/pet_p4_touch.c:93-119`，把"探测 0x5D → 失败试 0x14 → 建 panel IO → 建触摸驱动"的链路用自己的话写一遍，标注每步用的 API 名。
2. **📍阅读**：`touch_core.c:42-70` 的状态机里，长按事件为什么加 `long_press_emitted` 标志？去掉它每 15ms 会发生什么？
3. **🔍追踪**：`grep -n "pet_p4_touch_process" main/` 找到主循环消费触摸事件的函数，跟踪一个滑动事件从队列取出后经过了哪些处理。
4. **🔧动手**：把 `PET_P4_TOUCH_SAMPLE_MS` 从 15 改成 60，构建烧录后滑动屏幕，描述手感变化；再改成 5，观察是否和 15 有可感差异。
5. **💭思考**：本板触摸 RST/INT 都接的是 `GPIO_NUM_NC`（:107-108，即没接）。这解释了为什么用轮询而不是中断？如果 INT 接了，中断方案的完整链路会长什么样（注意 ISR 里不能做什么）？

## 自测与参考答案

- **练习2**：只要还按着，`now - start >= 700` 每个 tick 都成立，会每 15ms 连发一次长按事件；标志保证"一次按压最多一个长按"。
- **练习4**：60ms 采样约 16fps 的触摸更新率，滑动跟手性明显变差、轻点可能被当成滑动；5ms 和 15ms 的人眼差异很小——15ms 是"够用的最省"选择。
- **练习5**：INT 脚悬空 → 无法收到"有新坐标"硬件通知，只能轮询。有 INT 时：ISR 只做"给任务发通知"（ISR 里不能碰 I2C/日志/ malloc），任务被唤醒后再走 I2C 读坐标——即"中断唤醒 + 任务读数据"的分工。

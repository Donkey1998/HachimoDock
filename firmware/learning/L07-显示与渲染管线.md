## 学习目标

1. 掌握 esp_lcd 的三层模型：总线 → panel IO → panel
2. 理解帧同步（on_refresh_done + 信号量）与背光双路径

## 零基础补给站

| 术语 | 一句话解释 |
|---|---|
| 像素 / 分辨率 | 屏幕由小方格（像素）组成；480×640 = 宽 480 列 × 高 640 行 |
| 帧缓冲（framebuffer） | 内存里的一块大数组，每个元素是一个像素的颜色——**往数组写值=往屏幕画画**。`uint16_t buf[640*480]` 就是整个屏幕 |
| RGB565 | 用 16 位存一个像素：红 5 位、绿 6 位、蓝 5 位（绿多一位因为人眼对绿最敏感）。省一半内存的常用格式 |
| DMA | 直接内存访问：专用"搬运工"硬件替 CPU 搬数据（帧缓冲→屏幕），搬运期间 CPU 可以干别的——大批量数据传输的标准配置 |
| 撕裂 / 垂直同步 | 屏幕"读到一半"时你改了帧缓冲→上半屏旧图下半屏新图。对策=等屏幕刷完一帧（垂直同步信号）再换内容——本课的信号量方案就是软件版 |
| 双缓冲 | 准备两块帧缓冲轮流用：画进后台那块、画完整个换上前台那块，观众永远看不到画到一半的图 |
| MIPI-DSI | 手机/平板屏幕的高速标准接口（好几对差分线、高带宽）。老一辈屏幕用 SPI 慢慢刷——本板这块屏走 DSI |
| PPA | P4 芯片里的 2D 图形加速器，旋转/缩放这种"笨重搬运"它来干，CPU 省下来 |

## 讲解

### 7.1 esp_lcd 三层模型（ESP-IDF 显示驱动的通用套路）

无论屏多复杂，ESP-IDF 把它拆成三层，初始化顺序固定：

```
① 总线层：esp_lcd_new_dsi_bus()        // MIPI-DSI 控制器（数据怎么传）
② 命令层：esp_lcd_new_panel_io_dbi()    // 向屏幕发初始化命令的通道
③ 面板层：esp_lcd_new_panel_st7701()    // 面板对象：时序、分辨率、draw_bitmap
```

本项目面板是 ST7701S 2.8" 480×640，**MIPI-DSI 单数据 lane @800Mbps**，RST=GPIO27，DPI 像素时钟 24/25MHz（按芯片版本）。第②层的"初始化命令"是一串写给屏幕控制器的寄存器序列（厂商提供，换屏型就得换这张表）——它在 BSP 源码 `components/esp32_p4_wifi6_touch_lcd_4_3/` 的 display 实现里，本项目的 `esp_lcd_st7701` override 组件配合做了 `skip_mipi_id_read`（不读面板 ID，链路只写）。

调用链：`pet_p4_lcd_init()`（`main/pet_p4_lcd.c:84-123`）→ BSP 的 `bsp_display_new()` 完成上述三层装配。

**和安卓类比**：`draw_bitmap` ≈ `Surface.lockCanvas()/post()`；三层模型 ≈ HAL 的 Gralloc/HWC 分层——都是"把像素弄上屏"的标准化分层。

### 7.2 帧同步：异步 DMA + 完成回调

`esp_lcd_panel_draw_bitmap()` 把帧缓冲交给 **DMA 硬件搬运**后立刻返回（不等传完）。如果上一帧还没传完就写下一帧，会撕裂。对策：

1. 初始化时注册 `on_refresh_done` 回调（`pet_p4_lcd.c:93-100`）
2. DMA 传完一帧，回调在 ISR 上下文里**释放二值信号量**
3. 渲染循环 `xSemaphoreTake` 等这个信号量（超时 250ms，:215-230）——等价于"垂直同步"

第03课说的"信号量当完成事件用"，就是这里。

### 7.3 背光的双路径设计

背光 GPIO26 有两种控制方式，各有用途：

- **LEDC PWM 路径**（BSP 实现）：5kHz/10bit 调亮度，日常用
- **GPIO 直驱路径**（`pet_p4_lcd.c:46-61` 的 `force_lcd_backlight_gpio`）：强行拉高/拉低，**启动最早的灭屏用它**（:63-67，`pet_p4_lcd_prepare_boot`，见第04课步骤1）——因为 LEDC 还没初始化时就必须把屏黑掉

对称的亮屏 `pet_p4_lcd_reveal()`（:125-139）在第04课步骤13——**首帧渲染成功后**才亮，用户永远看不到花屏。这一对函数只有十几行，却是"上电视感"的产品细节。

### 7.4 渲染管线全景：逻辑横屏与物理竖屏的分离

物理面板是 480×640 **竖**屏（桌搭宠物的自然形态），但业务画面（宠物动画、气泡、组件卡片）是 640×480 **横**屏逻辑设计的。中间靠硬件加速旋转弥合：

```
业务层：永远画 640×480 横屏 RGB565 逻辑帧（PSRAM，renderer.c:4277 附近分配）
    ↓ 软件绘制（含 H.264 解码出帧、JPEG 硬解）
PPA SRM 旋转加速：640×480 → 480×640（renderer.c:4379-4396，rotate_landscape_to_panel）
    ↓
esp_lcd_panel_draw_bitmap() DMA 送面板双缓冲（renderer.c:4490-4491）
    ↓
等 on_refresh_done 信号量
```

PPA（Pixel Processing Accelerator）是 P4 片上的 2D 加速器，旋转这种"笨重搬运"交给它，CPU 省下来给 H.264 双核软解（`renderer.c:1652` 起，任务钉 core 1）。

**这个分离让谁变简单了**：所有业务代码（宠物、气泡、游戏、组件渲染）只管横屏坐标，不用关心屏怎么装的；代价是每次出帧多一道旋转。注意第06课埋的伏笔：**触摸坐标是竖屏物理坐标系**，所以输入侧要做坐标换算——一进一出，各守各的坐标系。

### 7.5 JPEG/H.264 直通（概览即可）

- JPEG：P4 片上 JPEG 硬解（`renderer.c:4404-4413`），失败回退 TJPGD 软解
- H.264：形象动画是 H.264 视频片段，双核软解（esp_h264 组件）直通面板播放，不解码成通用帧走 UI 合成——**为省内存走的专用快路径**

细节留到第12课，现在知道"渲染器有三条出帧路径：软件绘制 / JPEG / H.264 直通"即可。

## 练习

1. **📍阅读**：读 `main/pet_p4_lcd.c:84-123` 的 `pet_p4_lcd_init()`，按顺序列出它调用的函数，对照 7.1 的三层模型归类。
2. **📍阅读**：读 `pet_p4_lcd.c:46-61` 和 `:63-67`，回答：为什么灭屏能用 GPIO 直驱，而调亮度必须走 LEDC PWM？
3. **🔍追踪**：在 BSP 源码（`components/esp32_p4_wifi6_touch_lcd_4_3/`）中找到 ST7701S 的初始化命令表（一串寄存器写入），记下文件和大致行号。观察命令序列末尾是不是有一条"睡眠退出/显示开"类命令。
4. **🔧动手**：用桌面端连接设备后，触发 `debug/screenshot`（协议见 [protocol.md](../protocol.md) 的 debug 节），拿到一张屏幕截图——这是渲染器的输出快照，以后调试 UI 的利器。
5. **💭思考**：如果把逻辑帧也改成 480×640 竖屏（和面板一致），哪层代码变简单、哪层变复杂？PPA 旋转还需要吗？触摸坐标换算呢？

## 自测与参考答案

- **练习2**：灭屏只需要"最黑"，GPIO 拉低即可，任何时刻可用；调亮度需要 PWM 波形（占空比=亮度），必须等 LEDC 初始化。启动早期 LEDC 未就绪，所以直驱路径是必需的降级手段。
- **练习5**：业务层所有动画/布局要按竖屏重设计（变复杂）；管线层少了 PPA 旋转（变简单）；触摸坐标反而不用换算了。这是"贴近硬件简单"还是"贴近人类内容设计简单"的取舍——本项目选了后者，因为内容横屏更自然。

## 零基础补给站：读大 C 文件的五件语法武器

这五个语法模式覆盖了本课五个大文件里 90% 的"看着费劲"：

| 语法 | 含义 | 在大文件里的样子 |
|---|---|---|
| `static`（函数/全局变量前） | "只在本文件可见"——C 的私有化机制 | 每个模块一大把 `static void xxx()`：这些是内部 helper，不用跨文件找它们的调用者 |
| 函数指针表 | 把函数存进数组/结构体按需调用 | 协议分发的 topic→handler 表；`on_refresh_done` 回调——安卓 OnClickListener 的 C 写法 |
| 位运算三套路 | 置位 `x \|= (1<<n)`；清零 `x &= ~(1<<n)`；翻转 `x ^= (1<<n)` | 标志位管理、寄存器操作——第00课的 51 直觉直接复用 |
| `goto cleanup` | 错误集中跳到函数尾统一释放资源 | C 嵌套错误处理的惯用法（Linux 内核风）；不是邪恶，是没 RAII 时的纪律 |
| `const` / `volatile` | const=只读承诺；volatile=禁止编译器缓存优化 | `const` 保护不该改的配置表；`volatile` 用在 ISR/多核共享的标志上——两个连用 `const volatile` 表示"我只读它，但别人会改它" |

## 专题一：渲染器 `main/pet_p4_renderer.c`（4563 行，最推荐）

**读什么**：头部 `[Input]/[Output]/[Pos]/[Sync]` 设计注释（RGB565 帧管线 + H.264 直通路径的官方自述）；三条出帧路径的入口：
- 软件绘制逻辑帧（PSRAM 分配，:4277 附近）
- H.264 解码（:1652 起，双任务钉 core 1，任务名 `h264-pack`，:4360）
- JPEG 硬解 + TJPGD 回退（:4404-4413）
- PPA 旋转收尾（:4379-4396，:4490-4491）

**配套测试**：`tests/p4_h264_replay_test.py`（把真实解码器在主机上回放对比）、`tests/p4_component_center_test.py`（组件卡片渲染）。

**思考题**：为什么 H.264 直通面板而不解码进逻辑帧合成？（提示：内存带宽与 OTA 槽约束）

## 专题二：PetUI 组件运行时 `main/pet_p4_miniapp.c`（4317 行）

**是什么**：声明式组件（`.clawpkg` 包，如股票、木鱼、番茄钟）的运行时——PC 端把组件（JSON 描述 + 资源）推到设备，固件解析并驱动显示。**不执行任意脚本**，只有受限的组件模型（状态机/精灵/碰撞）——安全边界清晰。

**读什么**：头部注释；组件生命周期（安装→激活→运行→卸载）；和 `main/pet_p4_widget_data.c`（PC 每 2s 推的实时数据快照如何进入组件）。

**配套测试**：`tests/petui_validator_test.py`（组件校验器+模拟器）、`tests/p4_component_realtime_test.py`（真实输入分发+stub）。

**动手**：在 `pc/builtin-clawpkgs/` 挑一个组件包解开看结构，再经桌面端重装到设备。

## 专题三：游戏引擎 `main/pet_p4_game.c`（1083 行）

**是什么**："无堆、无脚本"（heap-free, script-free）的 2D 游戏引擎，支撑贪吃蛇、Flappy 等内置游戏。固定网格、编译期常量，零 malloc——嵌入式实时性的极端自律。

**读什么**：头部注释的固定网格常量定义；碰撞检测；帧循环。

**配套测试**：`tests/p4_game_logic_test.py`（主机上跑真实引擎逻辑）。

**思考题**：无堆设计牺牲了什么换来了什么？你会在什么场景拒绝这种设计？

## 专题四：OTA 升级 `main/pet_p4_ota.c`（836 行）

**是什么**：第11课"原则二"的完整实现：A/B 槽管理、镜像头独立校验、chipRevision 边界检查（v1/v3 镜像防互刷）、启动健康确认、失败回滚。

**读什么**：`pet_p4_ota_init` / OTA 开始-数据-结束流程 / 健康投票机制（结合 `main/pet_p4_main.c` 主循环里的 OTA runtime 健康检查）。

**配套测试**：`tests/factory_image_test.py`（出厂镜像的分页契约）。

**动手**（有风险，谨慎）：经桌面端做一次正常 OTA 升级，观察日志里的槽切换；**不要**尝试制造升级失败。

## 专题五：媒体与音乐 `main/pet_p4_media.c`（264 行）+ `pet_p4_media_codec.c`

**是什么**：音乐播放：PC 推 IMA ADPCM 压缩流，固件解压喂播放任务（衔接第08课音频）。

**读什么**：`media.c` 的导航/激活逻辑 + `media_codec.c` 的 IMA ADPCM 解码（文件头有 step_table，DPCM 经典算法，信号处理入门好材料）。

**配套测试**：`tests/p4_media_codec_test.py`（Rust 编码器 vs C 解码器 vs 参考实现三方对拍——跨语言一致性测试的好范例）、`tests/p4_media_runtime_test.py`。

## 通用方法论：大文件三步读法

1. **头部设计注释**：`[Input]/[Output]/[Pos]/[Sync]` 四行说清模块在系统中的位置——先读它决定要不要深入
2. **函数目录**：`grep -n "^static\|^void\|^esp_err\|^bool" 文件名` 列出全部函数签名，当目录用
3. **配套测试当文档**：测试断言是"模块行为的可执行规格说明"，比注释更不会说谎
